\section{Problem and Measurement}
\label{sec:prelim}

\subsection{The prediction problem}
\label{sec:problem}

We fix a capability set $\capset$ (here mathematical reasoning, code
generation, and multi-hop question answering) and study one quantity
per capability, the conditional loss $\Lc{c}$ of Eq.~\eqref{eq:taskloss}
below. For a compression method $m$ applied to a model, the target of
prediction is the post-compression capability vector, written relative
to a reference that is measured before the intervention:
\begin{equation}
\hat L_{m,c} \;=\; L^{\mathrm{obs}}_{c,\mathrm{ref}(m)}
\;+\;\widehat{\Delta}_{m,c}(\mathbf x,\mathbf z,\boldsymbol\theta_m).
\label{eq:interface}
\end{equation}
The reference differs by arm. For pruning and quantization it is the
dense source model itself, so $\widehat\Delta_{m,c}$ predicts the damage
$\Delta L_c=L_c(\text{compressed})-L_c(\text{dense})$. For distillation
it is the initial student, so the target is the signed transfer response
$\delta_c=L_c(S_{\mathrm{KD}})-L_c(S_0)$ of the student to the teacher
traces; the gap between teacher and student size never enters this
quantity. The three arms therefore share an endpoint and an evaluation
protocol, and nothing else is assumed to be shared: whether one
functional form covers several arms is a question the data have to
answer (\S\ref{sec:synthesis}).

The inputs fall into three groups. The state vector $\mathbf x$ holds
what is observable about the source (or the student) before the
intervention: the parameter count $N_0$, counted throughout as the
number of entries of the transformer weight matrices (attention and MLP
projections; embeddings, output head, biases, and norms excluded), the
pretraining token count $D_0$ where it is disclosed, and the measured
dense capability vector $\mathbf L_0=(L_{0,\text{math}},L_{0,\text{code}},L_{0,\text{qa}})$.
Family identity and per-model fitted amplitudes are not basic
parameters; where a model uses them, we say so. The shared descriptors
$\mathbf z$ are the quantities on which arms can be compared: retained
density, bit-width, and the processed and unique training tokens of a
distillation run. The method controls $\boldsymbol\theta_m$ are the
per-arm settings held fixed by protocol (pruning criterion, quantizer,
student size, supervision recipe). We do not invent shared variables
for an arm that has none.

\subsection{Operational loss definition}
\label{sec:loss}

Each capability $c$ has a probe set $\probeset{c}$ of prompt and
reference pairs drawn once, with a fixed seed, from held-out benchmark
splits: MATH-500 for math, MBPP for code, and 2WikiMultihopQA for QA as
the primary benchmarks. The observable is the token-weighted
conditional cross-entropy of the reference completion given the prompt,
\begin{equation}
\Lc{c}(w)\;=\;\frac{1}{T_c}\sum_{(x,y)\in\probeset{c}}\;\sum_{t=1}^{|y|}
-\log p_w\!\left(y_t\mid x,y_{<t}\right),
\qquad T_c=\sum_{(x,y)\in\probeset{c}}|y|,
\label{eq:taskloss}
\end{equation}
with prompt tokens masked, sequences truncated to 1024 tokens, and the
model's own tokenizer throughout. The same definition, the same 64
measurement probes per capability, and the same scoring code are used
for every model state that is compared within a model. We report
native nats per token. Within-model differences $\Delta L_c$ are
computed on identical token sequences and are the only quantities that
enter predictors; absolute levels across tokenizers are not placed on
one numerical scale, and where families are compared the comparison is
made within family or in per-byte units in the appendix.

Three boundaries of this observable are stated once here. First, it is
the negative log-likelihood of a fixed reference, which tracks task
success closely for code and math on these benchmarks but is not a
task-success measure; a QA loss can fall while exact-match accuracy
does not rise (Appendix~\ref{sec:app_probes}). Second, the reference
distribution is the full solution; direct-answer and
given-reasoning-answer variants were measured for a subset of models and
differ from it (Appendix~\ref{sec:app_probes}), so the numbers here are
specific to the full-solution reference. Third, capability specificity
is supported by a prediction test, not assumed: within-capability
responses on an independent secondary benchmark (SVAMP, HumanEval,
TriviaQA) are predicted from the primary benchmark better than by
cross-capability responses for math and QA, whereas for code the
within-capability gain was not detected at the available resolution
(Appendix~\ref{sec:app_probes}). Gradient and Fisher statistics of the
dense model appear only as mechanism evidence in the appendix; they are
never prediction inputs.

\section{Problem and Measurement}
\label{sec:prelim}

\subsection{The prediction problem}
\label{sec:problem}

We fix a capability set $\capset$ (mathematical reasoning, code
generation, multi-hop question answering) and one observable per
capability, the conditional loss $\Lc{c}$ of Eq.~\eqref{eq:taskloss}.
For a compression method $m$ the target is the post-compression
capability vector written relative to a reference measured before the
intervention,
\begin{equation}
\hat L_{m,c} \;=\; L^{\mathrm{obs}}_{c,\mathrm{ref}(m)}
\;+\;\widehat{\Delta}_{m,c}(\mathbf x,\mathbf z,\boldsymbol\theta_m).
\label{eq:interface}
\end{equation}
For pruning and quantization the reference is the dense source, so
$\widehat\Delta_{m,c}$ predicts the damage
$\Delta L_c=L_c(\text{compressed})-L_c(\text{dense})$. For distillation
it is the initial student, so the target is the signed transfer
$\delta_c=L_c(S_{\mathrm{KD}})-L_c(S_0)$, and the size gap between
teacher and student never enters. The arms share the endpoint and the
evaluation protocol and nothing else by assumption; whether one form
covers several arms is a question for the data (\S\ref{sec:synthesis}).

The inputs fall into three groups. The state $\mathbf x$ is what is
observable about the source or student beforehand: $N_0$, counted
throughout as the number of entries of the transformer weight matrices
(attention and MLP projections; embeddings, output head, biases, and
norms excluded); the pretraining token count $D_0$ where disclosed;
and the measured dense capability vector
$\mathbf L_0=(L_{0,\text{math}},L_{0,\text{code}},L_{0,\text{qa}})$.
Family identity and per-model fitted amplitudes are not basic
parameters, and models that use them are said to. The shared
descriptors $\mathbf z$ are the coordinates on which arms can be
compared: retained density, bit-width, and the processed and unique
training tokens of a distillation run. The method controls
$\boldsymbol\theta_m$ are the per-arm settings held fixed by protocol
(pruning criterion, quantizer, student size, supervision recipe). No
shared variable is invented for an arm that lacks one.

\subsection{Operational loss definition}
\label{sec:loss}

Each capability has a probe set $\probeset{c}$ of prompt and reference
pairs drawn once with a fixed seed from held-out benchmark splits
(MATH-500, MBPP, and 2WikiMultihopQA as primary benchmarks). The
observable is the token-weighted conditional cross-entropy of the
reference completion given the prompt,
\begin{equation}
\Lc{c}(w)\;=\;\frac{1}{T_c}\sum_{(x,y)\in\probeset{c}}\;\sum_{t=1}^{|y|}
-\log p_w\!\left(y_t\mid x,y_{<t}\right),
\qquad T_c=\sum_{(x,y)\in\probeset{c}}|y|,
\label{eq:taskloss}
\end{equation}
with prompt tokens masked, sequences truncated to 1024 tokens, the
model's own tokenizer, and the same 64 measurement probes per
capability for every state compared within a model. We report native
nats per token. Within-model differences $\Delta L_c$ on identical
token sequences are the only quantities that enter predictors; absolute
levels across tokenizers are never placed on one scale.

Three boundaries apply. The observable is the negative log-likelihood
of a fixed reference, not a task-success measure: a QA loss can fall
while exact-match accuracy does not rise (Appendix~\ref{sec:app_probes}).
The reference is the full solution; direct-answer and
given-reasoning variants differ from it for math and QA
(Appendix~\ref{sec:app_probes}). Capability specificity is a tested
property: the response on an independent secondary benchmark is
predicted better from the same capability's primary response than from
another capability's for math and QA, whereas for code the
within-capability gain was not detected at the available resolution
(Appendix~\ref{sec:app_probes}, Fig.~\ref{fig:measurement}). Gradient
and Fisher statistics of the dense model appear only as mechanism
evidence in the appendix; they are never inputs.

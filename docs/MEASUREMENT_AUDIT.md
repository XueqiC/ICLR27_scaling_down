# Measurement and split audit — Stage A, 2026-09-04

CPU-only inspection of existing scripts/artifacts; no inference, new evaluation, or job access. **The current unit is completion-token-weighted CE nats per model-token. Within-model ΔL preserves the tokenizer, but does not make cross-tokenizer comparisons invariant.** The earlier ledger assertion that no absolute cross-tokenizer loss is compared is incorrect for V19; this audit supersedes it.

## Exact capability-loss construction

The shared evaluator is [`completion_loss`](../../analysis/v6_capability_geometry.py) (lines 375–406), called by V6 pruning, V10 quantization, and V12's `measure_capability_losses` (also used by V13/V15/V16). `build_probes` samples up to 128 rows per benchmark without replacement using one sequential NumPy RNG, seed 0; measurement takes positions `[1::2]` in the sampled list, normally 64 items/capability. These are **sample-list positions, not odd original dataset IDs**. V6 Fisher uses `[0::2]` from the same construction.

| Capability | Dataset / split | Exact prompt | Teacher-forced target |
|---|---|---|---|
| math | `HuggingFaceH4/MATH-500`, `test` | `Problem: {problem}\nSolution:` | One leading space + full `solution`, including reasoning; not just `answer` |
| code | `google-research-datasets/mbpp`, config `full`, `test` | `# Task: {text}\n# Write a Python function.\n` | Dataset `code`, without an added leading space or fence; tests are not in the loss prompt |
| qa | `framolfese/2WikiMultihopQA`, `validation` | `Context:\n{ctx_text}\n\nQuestion: {question}\nAnswer:` | One leading space + `str(answer)`, answer only |

For dict QA contexts, titles and sentence lists are zipped, sentence lists joined with spaces, each passage rendered `{title}: {body}`, passages joined with newlines, then clipped to the first **4,000 characters**. Non-dict context is `str(context)[:4000]`. A separate token cap follows; the actual question/tail can be lost under truncation. Exact truncated text was not saved by V6.

Tokenization is direct, **no chat template**. Prompt and completion are separately tokenized and each capped at 512 tokens (`max_len=1024`). Prompt uses `add_special_tokens=True`; completion uses `False` (no added BOS/EOS). Gemma gets a prompt BOS inserted if absent, with the prompt recapped to 512. The concatenation is clipped to its last 1,024 tokens. Truncation side follows tokenizer state for loss; it is not explicitly fixed or recorded there.

With `n_p` retained prompt tokens, logits `[:, :-1]` predict IDs `[:, 1:]`; CE is summed starting at shifted index `max(n_p−1,0)`. Thus the first target is the first completion token when the prompt is nonempty; prompt tokens receive no loss. Aggregate **sum of completion NLL over all items / total scored completion tokens**. This is not an average of item-average losses, accuracy, bits, bytes, or characters. PyTorch cross entropy uses natural logs. Empty-target behavior differs: V6 divides by `max(ntok,1)`; V12's helper rejects a capability with zero total targets.

## Cross-tokenizer comparison and remaining measurement work

- V17/V18/V20 pool or compare ΔL across models/families; each subtraction is usually within-tokenizer, but the resulting magnitudes still have different token units.
- V21 compares **source-referenced** post-training gaps across families; this includes a dense size/quality gap. V22 separates that from training gain. V22's reference-shift calculation explicitly subtracts Gemma/Qwen reference losses as an accounting diagnostic in recorded units, not a calibrated family effect.
- **V19 directly fits absolute per-token L across Gemma/OLMo/Muse tokenizers.** Its held-out sigmoid fit is empirical transport in those units, not measurement invariance. V15's easy-panel loss cannot be silently joined to V6/V12's default-panel loss.
- Example token denominators from V12 for the same named clean probes: Gemma math/code/QA **13,198/4,516/251**; Qwen **13,392/3,461/271**; OLMo7B **12,954/3,455/262**. Particularly short QA targets amplify style/answer-token effects. Neither V19 nor negative KD QA loss alone establishes behavioral QA improvement.
- **TO-DO / TO-MEASURE, not run:** freeze identical UTF-8 prompt/target strings and shared character/byte truncation boundaries, evaluate summed target NLL, then normalize by target UTF-8 bytes (or explicitly defined Unicode characters). Aggregate NLL sums / aggregate lengths, not model-token averages. Current aggregate losses/counts cannot reliably reconstruct this when truncation changes text. Record dataset revisions/item IDs, tokenizer and checkpoint revisions, scored text hashes, code revision, exact normalization/decoding, and seeds.

V17's `apply_precliff_filter` scans **all observed outcomes** by `(model, method, capability)` before V18 splits: first ΔL>1 and every stronger-compression cell are excluded. The 1-nat threshold is fixed, but test eligibility depends on test labels. Report these errors as conditional on the observed pre-cliff regime; they do not measure prospective detection of cliffs. Outcome filtering and held-out-cell bootstrap also understate the dependence among adjacent configs.

Canonicalize model aliases and fix family grouping. For claims about unseen **reference-source/family transfer**, additionally group every student sharing `(B_ref, revision)`; distinguish this from the student's own base checkpoint S0 and the API teacher. Keep conditional config tests separately labeled. Freeze probe IDs/text and eligibility rules; choose thresholds on training data and score prospective cliff decisions separately. Use source-group (and, when available, item/seed) uncertainty rather than treating configs as independent.

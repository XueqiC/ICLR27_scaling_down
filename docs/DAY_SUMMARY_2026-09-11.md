## 3. Round v7:组合选择规则 + 分能力 map + 独立确认(C53/C54)

**锁定的规则**(测量前写进 `analysis/final_rule.py`):
- 剪枝:已见尺寸未见密度 → math/code 幂形、QA 中位曲线;新尺寸/新阶段 → 三能力 L₀ + 中位密度曲线。
- per-channel 量化:新状态 → 每 bit 开发中位。
- 分组量化:已见状态 → math/code 分段插值、QA 中位;新状态 → 三能力每配置中位(冻结边界规则)。
- 蒸馏(同阶段小 student 作候选):student 参考 + 每能力常数(code/QA),math 用线性 student-state 形式;QA 只在 2Wiki。
- 选择:名义存储预算 r_max∈{0.20,…,1.00},可行实测配置中取预测绝对 loss 最小;输出 math / code / QA / 多能力(取最坏)四张 map;无明确赢家给候选集。

**面板**:从未测过的 4 个状态 160M@32k、410M@32k、1.4B@32k(范围内新阶段)、1B@64k(该尺寸新阶段;有 160M@64k、410M@64k 两个 v39 student 作蒸馏候选)。权重重新下载到私有缓存,blob 哈希与全部旧 revision 比对(全为新 blob)。每状态 dense + 18 配置(剪枝 4 密度、per-channel 5 bit、分组 3×3)。

**流程**:下载 → verify → dense(Ada)→ 冻结所有候选的预测 loss 与四张 map(锁定规则 + 旧 v64 source-conditioned law 集作对照,提交 869ec2e)→ 72 个配置(27 min)→ compare。读法测前定:某能力上锁定规则 regret ≤ 旧 law 的 map 且 < 只量化才算确认。

**结果**(每能力 68 格,regret nats / 方法命中率):

| 目标 | 锁定规则 | 旧 law(v64) | 只量化 | 只蒸馏(可行格) | 最便宜 | 判定 |
|---|---|---|---|---|---|---|
| math | 0.00001 (0.985) | 0.015 | 0.007 | 0.168 (17) | 1.77 | 确认 |
| code | 0.004 (0.956) | 0.112 | 0.010 | 0.248 (17) | 2.43 | 确认 |
| QA | 0.141 (0.765) | 0.214 | 0.253 | 0.052 (17) | 1.35 | 确认 |
| 多能力 | 0.0020 (1.000) | 0.00185 | 0.008 | 0.240 (17) | 2.43 | 回顾性(差 0.0002) |

无明确赢家候选集在四个目标上都 100% 包含 oracle 方法。

**map**(图 `rule_maps-1.png`):math/code 几乎全选量化;QA 的 map 不同——三个 32k 状态预算 ≥0.6 选剪枝,1B@64k 各预算选蒸馏,oracle 标记一致。旧 law 的 QA map 在这些格上选量化(错)。
